# puncturing

## Test Type
Basic Functionality

## Overall Description
A test that exercises 802.11be preamble puncturing, using a Pal as the AP so the puncture pattern
can actually be set (the real DUT can't be told which subchannels to puncture). The point of the
test is specifically to exercise Expert Analysis' puncturing-detection functionality, not just to
run traffic.

At a high level, the script:
* Sets attenuation on the configured attenuators/MPEs.
* Asks the Pal-as-AP for its allowed puncture patterns on the configured channel/bandwidth, and
  randomly selects one of them to apply.
* Configures the Pal AP with that puncture pattern, and configures the STA (optionally with
  multiple vSTAs) to associate to it.
* Sets up a sniffer to capture beacons and traffic.
* Runs the traffic `totalTests` times in a row (default 1), each time: starting the sniffer,
  running the traffic, stopping the sniffer, then immediately running `createReport.dataAnalysis()`
  on that iteration's pcap and result archive -- which parses captured beacons for the EHT operation
  element's Disabled Subchannel Bitmap (confirming which subchannels were actually punctured over
  the air), and compares each Pal endpoint's actual PHY rate against the theoretical un-punctured
  rate (via Expert Analysis' `getDRate`) to find direct evidence of the puncture's effect on
  throughput.
* Generates the final HTML report via `createReport.main()`.

## Executable Code
### puncturing.py
This is the main code. As always, it does the initial configuration: reading in the configuration
files, reading in the testbed configuration, setting up the directory for output files, etc. All of
the puncture-selection, AP/STA/vSTA/sniffer setup is done here. Per test iteration, it calls
`createReport.dataAnalysis()` right after stopping the sniffer (while that iteration's pcap/archive
paths are still at hand) and logs the result under a `Test_<N>` key in the result log, rather than
waiting until the very end the way most other scripts do.

### createReport.py
Does the real analysis, in two parts:
* `dataAnalysis()` -- run once per test iteration (called directly from `puncturing.py`, not from
  `main()`). Parses the pcap for beacons from the main traffic stream's transmitter/receiver,
  extracts the puncturing bitmap from the EHT operation element, and separately runs that
  iteration's archive through Expert Analysis (`getStats`/`objectify`/`crunch`) to get each Pal
  endpoint's actual RX/TX rate, MCS, bandwidth, and streams.
* `main()` -- assembles the full report: allowed/selected puncture patterns, then per-test-iteration
  sections showing the detected puncture bitmap, each endpoint's PAL stats, the theoretical
  un-punctured rate for comparison, and a direct "Evidence of puncturing" summary. **After all of
  that**, it now also appends the standard basic plots -- Throughput vs. Time (every
  throughput-labeled column, combined), and Bits Per Second/MCS/PHY Rate/Streams/Bandwidth vs. Time
  (RX and TX, every radio endpoint, combined) -- built independently by rediscovering and
  re-analyzing each iteration's result archive. Radio endpoints are labeled with their real name
  (resolved from Expert Analysis' endpoint-mapping comment lines) when available, falling back to
  "Pal Endpoint N" otherwise.

## Configurability
Configurable files are always, by default, params_test.json, and params_system.json.
params_system.json is for overall system configuration (IP addresses, DUT security, etc.)
params_test.json is for changes made to the test itself.

Key configuration includes: `usePalAsAP`/`palAPssid`/`palAPsecurity`/`palAPpassword`/`palAPchannel`
(the Pal-as-AP and its puncture-capable configuration), `palToUse`/`palToUseSniffer`, `vstaSettings`
(vSTA count, for multi-link puncturing scenarios), `band`/`primaryChannel`/`bw`/`nss`/`iface`,
`ulDl`/`iperfMode`/`trafficType`/`trafficBW`, `attensToUse`/`quadAttenStart`/`quadAttenStop`, and
`totalTests` (how many times to repeat the traffic run, each with independent puncture analysis).

## Output
This test produces the standard CSV/JSON/pcap/zip output (one archive per test iteration), plus the
HTML report (`Puncturing.html`) generated by `createReport.py`, now including both the
puncturing-specific evidence analysis and the standard basic plots.
