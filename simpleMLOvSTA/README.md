# simpleMLOvSTA

## Test Type
Basic Functionality

## Overall Description
A simple MLO (Multi-Link Operation) test using virtual STAs (vSTAs). A single physical Pal STA is
configured to operate multiple simultaneous links (one per MLO band member), and on each of those
links a configurable number of vSTAs are created and associated. Traffic runs across all of the
resulting vSTA links at once to exercise MLO operation.

At a high level, the script:
* Sets attenuation on the configured attenuators/MPEs.
* Optionally configures a second Pal as an MLO AP (if `usePalAsAP` is set), otherwise tests against
  the real DUT.
* For each MLO band marked as a "member", sets up the configured number of vSTAs and a traffic pair
  for each one.
* Associates the physical STA across all configured MLO links/vSTAs, and fixes up each traffic pair's
  IP addressing based on the per-vSTA IP mapping returned by setup.
* Runs the traffic `totalTests` times in a row (default 1), saving each run's result archive
  separately (`..._0.zip`, `..._1.zip`, etc.).
* Generates the final HTML report via `createReport.py`.

## Executable Code
### simpleMLOvSTA.py
This is the main code. As always, it does the initial configuration: reading in the configuration
files, reading in the testbed configuration, setting up the directory for output files, etc. All of
the MLO/vSTA-specific setup (bands, vSTA counts, IP mapping, traffic pairs) is done in this code.

Note: this script did not previously log any test info to the result log at all (no `testresultlog`
content), which would leave `createReport.py` with nothing to read. A basic test-info log entry
(matching the convention used by every other script) was added so the report can be generated.

### createReport.py
Newly added. Reads the result-log JSON above, finds **every** result archive this run produced (one
per `totalTests` iteration -- plots are labeled by iteration when there's more than one), and runs
each through Expert Analysis (zip2csv -> objectify -> crunch). For each iteration it produces the
standard set of plots -- Throughput vs. Time (aggregate and per vSTA link/traffic pair), and PHY
Rate/MCS/Bandwidth/Streams vs. Time (UL/DL) per radio endpoint -- plus two MLO-specific plots per
radio endpoint:
* **MLO vSTA Associated Count vs. Time**: configured vSTA count vs. actually-associated count.
* **MLO per-vSTA Association Status vs. Time**: one 0/1 line per individual vSTA, decoded from
  Expert Analysis' per-endpoint association bitmask -- the clearest way to see exactly which vSTA/link
  dropped or rejoined, and when.

There is no attenuation sweep in this test, so there are no RvR-vs-attenuation plots.

## Configurability
Configurable files are always, by default, params_test.json, and params_system.json.
params_system.json is for overall system configuration (IP addresses, DUT security, etc.)
params_test.json is for changes made to the test itself.

Key configuration includes: `palToUse` (the physical STA), `mloConfig_STA`/`mloConfig_AP` (which bands
are MLO members, and per-band bandwidth/streams/attenuation settings), `vstaSettings` (how many vSTAs
per band), `ulDl`/`iperfMode`/`trafficType`/`trafficBW` (traffic settings), `usePalAsAP` (test against
a Pal-based AP instead of the real DUT), and `totalTests` (how many times to repeat the traffic run).

## Output
This test produces the standard CSV/JSON/zip output (one zip archive per test iteration), plus the
HTML report generated by `createReport.py`.
